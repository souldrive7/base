## ③（消失濃厚 → 消失確定）の代替復元

- **WSL**: `wsl --install -d Ubuntu-24.04` で新規作成 → `init_wsl_workspace.ps1` で作業環境を初期化
- **WiFiパスワード**: 主要な回線はルーター本体のラベル／スマホの保存済みネットワークから再登録
- **アプリ一覧**: 本リポジトリの `setup/install-apps.ps1`＋`restore-phase2-20260615.ps1` が代替（クラウド記録から再構成済み）
- **.claude メモリ**: 再構築。今後は `%USERPROFILE%\.claude` を定期バックアップ対象に追加
- **AppData\Roaming**: アプリ再インストールで大半は再生成される。個別データ（ブラウザプロファイル等）はクラウド同期分で復旧

## Gドライブに関する追加調査（2026-07-03・完了）

「バックアップ先は `G:` という別ドライブだったのでは」との申告を受け追加調査。結果、この可能性も否定された。

- **クラウド側**: 「PCバックアップ_2026-06-30」フォルダを再検索したが、依然として空。ドライブ文字の違いはクラウド到達状況に影響しない（ローカルのドライブ構成に関わらず、アップロード自体が完了していない事実は変わらない）
- **ローカル側**: `Get-Partition` の結果、PC内蔵ディスクは NVMe 1台のみで、パーティションは System / Reserved / **C:（1.86TB）** / Recovery の4つだけ。隠れた別パーティションや2台目のディスクは存在しない
- **結論**: `G:` は「PC内蔵の別ドライブ」ではあり得ない。外付けドライブ／NASのマッピングだった場合は当該デバイスを接続すれば救出可能性が残るが、現状PCには存在しない。`subst` 等でCドライブ内フォルダに文字を割り当てていただけだった場合は、Windows.old調査で確認済みの「空プロファイル」に飲み込まれ消失している

## 最終結論（2026-07-03 時点でクローズ）

ローカル救出の全経路（Windows.old／Gドライブ）を調査したが、③に分類したデータ（AppData\Roaming 25GB、WSL 2ディストリ、WiFi/アプリ一覧、.claudeメモリ、Dev_Backup）は**復元不可能と確定**。
①（クラウド実在分）・②（GitHub実在分）は無事であり、被害は③の範囲に限定される。
以後の対応は上記「代替復元」の手順に従い、外付けドライブが後から見つかった場合はこの文書に追記して再調査する。
